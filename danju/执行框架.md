## 一、系统概览

一句话：**扫描件进、成品出**的单据流水线——入库单（JPG/PNG 扫描件走 OCR，带文字层的 PDF 直提免 OCR）识别入库，自动生成采购台账与验收单（明细超 17 项自动续页）；付款单**由数据库未付款入库单驱动**，发票 PDF 仅作辅助（用途线索 + 凭证归档）。

| 输入 | 处理 | 输出 |
|---|---|---|
| 入库单扫描件（jpg/png） | OCR → 数据库匹配 → 归档 | 采购台账（按月分表）、验收单 docx + PDF |
| 入库单 PDF（含文字层） | pdfplumber 直提结构化数据入库（零误差） | 同上 |
| 未付款入库单（DB） | 匹配付款单数据库取账户 → OOXML 填模板 | 付款单 xlsx + PDF、付款台账 |
| 发票 PDF（辅助） | 首页提取供应商/金额 → 供用途匹配与凭证 | invoices 表、归档副本 |
| 申购单 / 事项审批 PDF | 按金额匹配供用途 | 用途回写数据库 |

核心设计原则（脚本强制执行）：
- **数据库是唯一事实源**：台账/验收单/付款单全部从 `60_数据\单据.db` 派生，改数据只改库；
- **严禁编造**：OCR 看不清、用途有冲突、金额对不上，一律打 WARNING 列清单，由人工定夺，脚本不猜；
- **幂等**：同批文件重复跑不产生重复记录。

## 三、主流程执行框架（一键生成.py，步骤 0~14）

一次运行按序执行以下步骤，**每步前置检查，条件不满足安全跳过，不报错中断**：

| 步骤 | 做什么 | 输入 | 输出/副作用 | 校验与失败行为 |
|---|---|---|---|---|
| **0 自动分拣** | `10_输入` 根目录散放文件归位：文件名关键词→扩展名→PDF 首页内容三层判定；`<图片名>.ocr.txt` 侧车文件随对应图片一起归位 | 散放文件 | 移入对应子目录；判不了进 `10_输入\待确认` | 同名内容相同去重、不同自动加(2)避让；绝不静默丢文件 |
| **1 OCR 识别** | 逐张识别 `10_输入\入库单扫描件\*.{jpg,jpeg,png}`；**侧车优先**：图旁有 `<图名>.ocr.txt` 即视为人工校对结果直接采用并转存 MD5 缓存；其次读 MD5 缓存 | 扫描件图片 | 识别行文本（内存） | 引擎异常/读图失败→该图记空，WARNING |
| **1.5 PDF 直提** | 扫描件目录里的 PDF 用 `parse_pdf_receipt.py` 文字层直提（零误差），产出结构化入库单；图片型 PDF（无文字层）WARNING 转人工 | 入库单 PDF | 结构化数据（内存）待步骤2入库 | 无单号/无明细页→WARNING |
| **2 匹配入库** | 提取单号 `CGSH\d{12,}`，与 receipts 表匹配；无单号→自动补录（日期/供应商/明细三缺一即失败）；识别为续页（无单号）→沿用上张单号合并明细；**PDF 解析结果直接写库**（与图片链路同单号去重） | 识别结果 + DB | 新单据写入 DB；`all_records`/`all_receipts` | **交叉验证**：每行数量×单价=金额、行合计=单合计，不符只 WARNING |
| **3 扫描件归档** | 匹配成功的原件按 `naming.scan_name` 重命名移入 `40_归档\入库单扫描件` | rename_map | 输入目录清空该件 | 移动前判存在；归档命名冲突即避让 |
| **4 采购台账** | 按**每条记录自身日期**归入 `N月` 工作表（修复过跨月错归 bug），宋体写入，表尾合计 | all_records + 模板/已有台账 | `20_输出\台账\采购台账_2026.xls` | 按单号去重跳过已入账；模板缺工作表报 ERROR 跳该月 |
| **4.5 台账自检** | 台账 vs DB 逐单号比行数与金额，整单/部分缺失自动补入 | 台账 xls + DB | 修复后的台账 | 修复后仍不符→WARNING 列明细请人工 |
| **5~6 验收单 docx** | 解包 `验收单模板.docx`，逐单填日期+17 行明细；**超 17 项自动续页**（`accept_pages.py`，每页抬头/表头/签字栏完整，序号连续）；表头行保持模板原样 | all_receipts | `20_输出\验收单\验收单_单号_日期_供应商_金额.docx` | 续页打印提示"共 N 项物料分 X 页"；模板行不足→报错不静默 |
| **7 验收单转 PDF** | Word COM 导出（先剥除模板修订/保护标记防挂死）；`SKIP_PDF=1` 时跳过、由 `to_pdf.py` 补 | docx | **`30_待打印\*.pdf`** | Word 失败→soffice 回退（本机未装）；均失败→WARNING |
| **7.5 发票提取（辅助）** | pdfplumber 读 `10_输入\发票\*.pdf` 首页：价税合计（小写）、销售方名称；新 PDF 才入库 | 发票 PDF | invoices 表新增（usage 可为空） | 提取不完整→WARNING 跳过该张，不编造 |
| **8~14 付款单（入库单驱动）** | 对每张 **status≠paid 的入库单**：金额/供应商/物料取自 DB → 按供应商+金额匹配一张未消费发票作辅助（无发票也照常出单）→ 定用途 → 关键词匹配 `付款单数据库.xlsx` 取账户/开户行 → OOXML 填模板（大写金额逐位）→ xlsx 落 `20_输出\付款单` | receipts + 付款单模板/数据库 | 付款单 xlsx | 申购单与事项审批用途不一致→**熔断**，进结尾清单；未匹配供应商→WARNING 空账户 |
| **14 付款单转 PDF** | Excel COM（win32com）导出，失败回退 soffice | xlsx | **`30_待打印`** | 转后读回 6 字段逐项验证 OK/FAIL |
| **收尾** | 入库单标记 `status=paid`（防重复出单，重复入库不回退）；匹配到的发票移入 `20_输出\发票` + processed=1；付款台账按该单 DB 明细逐行追加；打印用途冲突清单与用途空值清单 | — | 付款台账_2026.xls | 结尾集中 WARNING，供人工补填 |
| **15 参考件归档** | 申购单/事项审批与发票一对一：文件名"金额N"已被 processed=1 发票或 paid 入库单消费 → 移入 `40_归档\<类型>\<日期>`，防止输入目录堆积 | 申购单/事项审批子目录 | 归档完成 | 未消费或解析不出金额的保留原地，绝不静默移动 |

## 四、数据流与状态流转

```
入库单:  10_输入\入库单扫描件 ─┬─jpg/png──OCR+匹配────▶ receipts/receipt_items(单据.db) ─▶ 台账月份页 / 验收单(>17项自动续页)
（散放自动归位）               └─pdf(文字层)──直提入库──▶       │(原件)
                                                              ▼ 步骤3
                                                   40_归档\入库单扫描件(规范命名)

发票PDF(辅助): 10_输入\发票 ──步骤7.5──▶ invoices(usage, processed=0) ─┐ 匹配到才归档
        申购单/事项审批(按金额匹配供用途)                                ▼
                                                    20_输出\发票(归档副本)
付款流:  receipts(status≠paid) ──步骤8~14──▶ 付款单 + 付款台账 + status=paid
```

关键状态：
- **入库单**：status `matched → paid` 单向，置 paid 后不再出付款单；`add_receipt` 重复入库保留 paid 不回退；补录用 `manage_db.py add`；
- **发票**：`invoices.processed` 0→1 单向；降级为辅助数据（用途线索+凭证），无发票付款单照常生成；用途为空会在每次运行结尾提示（已登记忽略项除外）；
- **OCR 缓存**：以图片内容 MD5 为键，图内容不变缓存有效，重命名不影响；人工校对用**侧车文件** `<图名>.ocr.txt`（与图同目录，首次运行自动转存 MD5 缓存）。

### 5.2 脚本分工

**根目录（执行引擎本体，8 个）**：`一键生成.py` 主流程 ｜ `run.py` 解释器自适应入口 ｜ `一键生成.bat` 双击入口 ｜ `paths.py` 路径中枢（BASE 自适应、`DJ_BASE` 可覆盖） ｜ `db.py` 数据访问 ｜ `naming.py` 命名规范 ｜ `init_db.py` 建库（库非空无源拒重建） ｜ `requirements.txt` 依赖清单。

**80_工具（12 个）**：

| 脚本 | 角色 |
|---|---|
| `ocr_local.ps1` | Windows 内置中文 OCR，行式输出，缓存优先（步骤1 调用） |
| `parse_pdf_receipt.py` | PDF 入库单文字层解析（步骤1.5，主流程 import） |
| `accept_pages.py` | 验收单分页渲染，>17 项自动续页（步骤5~6 与 rebuild 共用） |
| `payment_ledger.py` | 付款台账追加（主流程 import） |
| `manage_db.py` | 查库/补录/改用途/统计 |
| `build_ocr_cache.py` / `seed_db.py` | 历史种子工具（内置数据为已清除的 8 月单据，本机已无对应图片，仅留档） |
| `rebuild_outputs.py` | 从 DB 重建台账+验收单 docx（口径与主脚本同步） |
| `to_pdf.py` | docx→PDF 补转，输出 30_待打印 |
| `run_report.py` | 主流程包裹器：批归档(archive_outputs)+日志落盘(70_)+待打印暂存；**现由 `一键生成.bat → run.py report` 默认调用** |
| `archive_outputs.py` | 成品批归档 + 待打印暂存（run_report 调用） |
| `accept_doc.py` | ⚠️ 孤岛：合并成册渲染变体，主流程从未 import；其续页实现为旧版（裁表尾）、表头写单号违背现行口径，仅其"金额熔断"思想可参考（详见未接入方案盘点报告） |

## 七、标准操作（SOP）

- **日常跑批**：单据丢 `10_输入` → 双击 `一键生成.bat` → 看结尾 WARNING 清单 → `30_待打印` 打印、`20_输出` 取台账。
- **补录识别失败的单据**：`python 80_工具\manage_db.py add CGSH单号`（对照原图逐行录入）→ 重跑主流程自动出台账/验收单。
- **修正识别结果（首选侧车）**：在图片旁放同名 `<图名>.jpg.ocr.txt`（一行一字段：编号/名称/规格/单位/数量/单价/金额，对照原图，严禁凭记忆改数）→ 重跑即自动采用并转存缓存；也可改 `90_临时\ocr_cache\<MD5>.txt` 或删除该缓存重识别 → `rebuild_outputs.py` 重建成品。
- **PDF 缺失**：关 Word → `python 80_工具\to_pdf.py`。
- **成品与库不符**：`python 80_工具\rebuild_outputs.py`（docx）+ `to_pdf.py`（PDF）。
- **新机器部署**：拷目录 → `pip install -r requirements.txt` → `python -c "import paths; paths.ensure_dirs()"` → `python init_db.py` → 放 4 模板 → 空跑验证各步骤"跳过"无报错。

## 八、风险与注意事项

- **R1 缺单号补录脆弱**：OCR 三要素缺一即失败丢单，靠校对缓存+manage_db 缓解；
- **R2 交叉验证 WARNING 需人工**：脚本提示不篡改，核 `40_归档` 原图；
- **R3 转换依赖桌面组件**：Word/Excel 被占用或 COM 不可用会使 PDF 环节空转（docx/xlsx 不受影响）；
- **R4 双 Python 解释器**：见第六节，入口统一走 bat；
- **R5 同供应商同金额撞名**：付款单命名含发票名+简称+金额，仍可能同名，重名避让机制兜底；
- **R6 发票金额正则**：`（小写）价税合计` 命中不了真实票版式时金额/用途为空，按 WARNING 人工补；
- **R7 改动边界**：本项目脚本与成品格式的**任何新增操作**（超出原仓库既有行为的）须先经用户确认（2026-09-06 明确规则）。
