## 分步详解

### 步骤 0：自动分拣（散放文件归位）

对 `10_输入` 根目录里的每个文件，按三层顺序判定归属：

1. **文件名关键词**：含"入库单/扫描件"→ 入库单扫描件目录；含"发票"→ 发票；含"申购"→ 申购单；含"审批"→ 事项审批
2. **扩展名**：.jpg/.jpeg/.png 且文件名判不出 → 入库单扫描件目录
3. **PDF 读首页内容**（pdfplumber 取前 1500 字）：
   - 含"价税合计/（小写）/销售方/发票" → 发票目录
   - 含"申购" → 申购单目录；含"审批" → 事项审批目录
   - 含"入库单" → **入库单扫描件目录（走步骤 1.5 文字层解析）**
4. 都判不了 → `10_输入\待确认`，打印提示人工归类，**绝不丢弃**

同名冲突：内容 MD5 相同视为重复副本删除；不同则自动加 `(2)` 避让。
直接放在子目录里的文件不受本步影响。

### 步骤 1：图片扫描件 OCR（JPG/PNG）

对 `10_输入\入库单扫描件\` 下每张图片：

1. **侧车校对优先（本次新接入）**：图片旁若有同名 `<图名>.jpg.ocr.txt`（一行一字段的人工校对结果，随图自动归位），直接采用并按图片内容 MD5 转存正式缓存——**人工纠错无需手算 MD5 命名缓存文件**
2. 复制到纯英文临时目录改名 `img_NNNN.jpg`（规避 OCR 引擎不支持中文路径）
3. 调 `80_工具\ocr_local.ps1`（Windows 内置中文 OCR，zh-Hans-CN，CPU 模式）
4. 解析输出：取两行 `---` 分隔线之间的文本行
5. **MD5 缓存优先于引擎**：若 `90_临时\ocr_cache\<图片MD5>.txt` 存在（人工校对过的结果），直接采用、跳过引擎

⚠️ 已知局限：OCR 按视觉块输出、会丢失表格行列结构，数字可能出错（小数点丢失、形近字）。这正是引入 PDF 直提链路的原因。

### 步骤 1.5：PDF 版入库单文字层解析（新增，零误差通道）

对扫描件目录里每个 .pdf：

1. `80_工具\parse_pdf_receipt.py` 用 pdfplumber 逐页直提文字层
2. 每页识别：**入库单号**（CGSH+12位数字）、**日期**、**供应商名称**（行首匹配"经营部/公司/厂/店…"）、**物料行**（编号 名称 规格 单位 数量 单价×2 金额×2）、**合计金额**（取票面合计）
3. 同单号跨页自动合并；无单号页并入上一单
4. 无文字层（图片型 PDF）→ 打印 WARNING 请人工转成图片扫描件，不静默出错
5. 产出结构化数据，等步骤 2 入库

### 步骤 2：匹配数据库 / 入库

**图片链路**：OCR 提取单号 → 查库。库里已有 → 直接用库数据生成台账/验收单；库里没有 → 自动从 OCR 行提取日期/供应商/物料/合计并写库（提取失败则计入未匹配告警）。

**PDF 链路**：解析结果直接 `db.add_receipt()` 写入 receipts/receipt_items 表，并同步汇入台账明细流和验收单数据流。带两道去重守卫：同一次运行内重复单号跳过；同一单号已被图片链路处理过的跳过。

**两条链路都强制执行交叉验证**：
- 每行：数量 × 单价 ≈ 金额（容差 0.5 元）
- 整单：Σ物料金额 ≈ 票面合计（容差 1 元）
- 不满足 → 打印 WARNING 请人工核对，**严禁自动补全或编造数据**

### 步骤 3：原件归档

匹配成功的扫描件按统一规范改名移入 `40_归档\入库单扫描件\`：
`入库单扫描件_<单号>_<YYYYMMDD>_<供应商简称>.jpg/.pdf`

### 步骤 4：生成采购物资台账（xls）

1. 已有 `20_输出\台账\采购台账_2026.xls` 则在其上追加，否则从 `50_模板\采购物资台帐.xls` 新建
2. **按每条记录自身日期**分组写入对应月份工作表（1月~12月页）
3. 写入前查重：该月已存在的入库单号整单跳过 → **重复运行幂等**
4. 列结构：物料编号/名称/规格/单位/数量/单价/金额/采购日期/入库单号/供应商/事由，宋体，合计行加粗
5. 台账末尾含药剂/供应商/类别三张汇总表页

### 步骤 4.5：台账自检

逐单号核对「DB 明细项数、金额」vs「台账行数、合计」：
- 一致 → 打印"全部 N 个单号一致"
- 台账缺行 → 自动从 DB 补入缺失记录并重算合计，二次验证
- 补不回来的（金额对不上等）→ WARNING 请人工检查

### 步骤 5~6：生成验收单（docx，自动续页）

1. 解包 `50_模板\验收单模板.docx`
2. 由 `80_工具\accept_pages.py` 直接改写 OOXML（word/document.xml）：每页填验收日期 + 17 行明细（序号/物资名称/规格型号/单位/数量），不足清空
3. **物料超过 17 项自动续页**：每页复制完整模板表格（抬头、表头、签字栏、遗留问题栏每页齐全），序号跨页连续（…17 | 18…），页间插入分页符，控制台打印"共 N 项物料，分 X 页打印"
4. 重新打包成每张入库单一个 docx，命名 `验收单_<单号>_<日期>_<供应商>_<金额>.docx` → `20_输出\验收单\`

### 步骤 7：验收单转 PDF

1. 预清理：剥离模板自带的限制编辑保护、修订记录、批注（防 Word 无头调用弹框挂死）
2. 本机 Word 组件（COM）批量导出 PDF → `30_待打印\`
3. 沙箱/无 Word 环境可设 `SKIP_PDF=1` 先出 docx，之后用 `80_工具\to_pdf.py` 补转

### 步骤 7.5：发票信息自动提取（辅助数据）

对 `10_输入\发票\` 里**尚未入库**的每张发票 PDF：

1. pdfplumber 提取：价税合计（"（小写）"后金额）、销售方名称（优先表格单元格定位，回退文本行匹配）
2. **用途解析**（四级回退）：DB 已有 → 发票文件名"（用途）金额" → 申购单按金额匹配 → 事项审批按金额匹配；**申购单与事项审批都有且不一致 → 放弃自动采用**，列入冲突清单待人工
3. 写入 invoices 表（filename/seller/amount/usage/processed=0）
4. 定位说明：**自 v5 起发票不再是付款单的驱动数据源**，仅作为用途线索与付款凭证的辅助依据

### 步骤 8~14：生成付款单（数据库驱动）

对每张**未付款入库单**（`receipts.status != 'paid'`，按日期排序）：

1. **供应商、金额、物料明细全部取自数据库**：金额=入库单 total，供应商=receipts.supplier，物料=receipt_items
2. **发票仅作辅助**：按供应商名称互认 + 金额一致（优先）从 invoices 表匹配一张未消费发票，用于提供用途线索；匹配不到也照常出单，打印"发票可后补"
3. **用途解析**：发票记录 → 发票文件名 → 申购单/事项审批按金额匹配；全为空则用途留空并 WARNING
4. **匹配供应商账户**：用 `50_模板\付款单数据库.xlsx`（供应商→开户行/账号/电话/地址）按名称关键词模糊匹配；未匹配到则账户留空并 WARNING
5. **填写付款单模板**：解包 `付款单模板.xlsx`，改写 OOXML——金额大小写（壹贰叁…自动换算）、收款单位、日期、用途等 → `20_输出\付款单\付款单_<供应商>_<金额>.xlsx`
6. Excel 组件转 PDF → `30_待打印\`（失败回退 soffice）
7. **自动验证**：回读 xlsx 逐格核对 6 个关键字段（用途/收款单位/账号/开户行/地点/电话）
8. **登记付款台账**：`20_输出\台账\付款台账_2026.xls`，物料行**直接取该入库单的 DB 明细**（不再按金额反查），付款单号幂等去重
9. **标记已付款**：`receipts.status='paid'`（`add_receipt` 冲突更新时保留该状态不回退）→ **同一批单据重复运行不再重复出付款单**
10. 匹配到发票的：发票原件改名归档 → `20_输出\发票\`（`发票_<供应商>_<金额>.pdf`，规则不变），invoices 表标记 processed=1

### 收尾

- 打印汇总：`全部完成! 采购台账(N条) + 验收单(N份) + 付款单(N份)`
- 若存在**用途不一致冲突**：红框清单逐张列出发票/金额/两个来源的用途，提示人工补填
- 若 DB 中仍有用途为空的发票：列出供人工巡检
- **步骤 15 参考件归档**：申购单/事项审批与发票一对一，文件名"金额N"已被已处理发票或已付款入库单消费的，自动移入 `40_归档\<类型>\<日期>`（未消费的保留原地）——输入目录不再堆积
- 运行链路自带三件事（bat 双击时）：旧批成品移入 `40_归档\<类型>\<日期>`、完整输出落 `70_日志\运行报告_*.log`、成品复制暂存 `30_待打印\`（幂等去重）

## 目录与数据流向速查

| 目录 | 角色 | 谁在读写 |
|---|---|---|
| `10_输入\` | 唯一入口（散放即分拣） | 人工写入，步骤0 归位 |
| `10_输入\入库单扫描件\` | JPG=OCR 通道 / PDF=文字层通道 | 步骤1、1.5 读取 |
| `60_数据\单据.db` | **唯一数据源**（SQLite：receipts/receipt_items/invoices/meta） | 步骤2、7.5、8~14 读写 |
| `20_输出\台账\` | 采购台账 + 付款台账（xls，按年） | 步骤4、8~14 追加 |
| `20_输出\验收单\`、`20_输出\付款单\` | docx/xlsx 源文件 | 步骤5~6、8~14 |
| `30_待打印\` | 全部待打印 PDF 汇集处 | 步骤7、8~14 |
| `40_归档\` | 已处理原件（规范改名） | 步骤3 |
| `50_模板\` | 只读模板 + 付款单数据库（**含敏感账户信息，不入公开仓库**） | 各生成步骤 |
| `70_日志\` | 运行日志 | 收尾 |
| `90_临时\` | OCR 缓存（人工校对优先）、模板解包中间件、备份 | 各步骤 |

## 三条可靠性原则（贯穿全流程）

1. **不编造**：所有提取失败/匹配冲突/交叉验证不通过都打 WARNING 交人工，程序绝不猜数
2. **幂等**：台账按入库单号去重、发票按 processed 标记去重，同一批文件重复运行不产生重复数据
3. **数据单一来源**：SQLite 库是唯一事实源，台账/验收单/付款单全部从库生成，可用 `80_工具\rebuild_outputs.py` 随时整体重建
